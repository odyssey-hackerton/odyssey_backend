# Odyssey 웹 프론트

게시 전에 사진·글 속 개인정보를 확인하고 보호 편집하는 6단계 화면이다.
**서버 없이 브라우저에서만 동작한다.** 사진과 글은 어디에도 전송하지 않고, 새로고침하면 사라진다.

## 실행

Node.js 20 이상.

```sh
npm ci
npm run dev
```

http://localhost:5173 에서 확인한다. 정적 파일만 있으면 되므로 `npm run build` 결과(`dist/`)를 어떤 웹 서버에 올려도 동작한다.

## 화면 흐름

| 단계 | 하는 일 |
| --- | --- |
| 01 홈 | 새 게시물 보호로 시작. 이전 게시물 점검은 준비 중 |
| 02 업로드 | 사진 최대 4장(JPG·PNG·WebP, 한 장 10MB) + 함께 올릴 글 |
| 03 분석 결과 | ① 탐지 + ② 위험 분석 결과. **추천 보호안 보기** → 04, **심층 분석**(준비 중) → 보호 편집 없이 06 |
| 04 보호 편집 | ③ 추천 보호가 적용된 미리보기. 영역 A, B, C …마다 가리기(흐리게/덮기)·지우기·그대로 두기. 바꾸기·잘라내기는 준비 중. 미리보기로 결과만 보고 다시 편집 가능. **적용**하면 글에 단서가 있을 때 원래 글과 고친 글을 보여 주고 적용 여부를 고른다 |
| 05 재검증 | 노출 위험 전후, 처리 내역, 그대로 둔 단서. **추가 보호** → 04, **잔여 위험 확인 후 계속** → 06 |
| 06 공유 | 공유하기(Web Share)·다운로드·본문 복사 |

## 브라우저에서 하는 일

- **단서 찾기**
  - 사진 영역: 예시 영역(예시 카페 사진 기준 비율)을 모든 사진에 표시한다. 실제 AI 탐지가 아니다.
  - 글: 전화번호·이메일을 찾는다.
  - 사진 파일 정보: 파일 앞부분에서 EXIF를 찾는다.
- **보호 편집**: Canvas로 그린다. 흐리게는 영역을 줄였다 키우고, 덮기·지우기는 단색으로 채운다(자연스러운 지우기는 준비 중). 결과는 PNG로 다시 그려 EXIF가 남지 않는다.
- **글 가림**: 단서 부분을 `[가림]`으로 바꾸고, 지우기면 삭제한다. AI 워커(stages/transform.py)와 같은 규칙이다.
- **진행 표시**: ① 탐지 → ② 위험 분석, ③ 변환 → ② 재검증 단계를 진행 표시로 보여 준다. 재검증 결과의 노출 위험은 그대로 둔 단서의 위험 등급으로 계산한다.

## 검사

```sh
npm test
npm run build
```

테스트는 파일 수/크기/형식, 잘못된 영역 좌표, 여러 사진의 예시 영역, 글 가림 규칙, 영역 라벨(A, B, C), 위험 점수, EXIF 확인을 다룬다.

공유 버튼은 다운로드된 파일과 본문을 `navigator.share`로 전달한다. HTTPS와 지원 브라우저가 필요하며, 미지원 환경에서는 다운로드·본문 복사를 안내한다.
