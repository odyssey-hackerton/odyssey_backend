# Odyssey React 테스트 UI

사용자가 제공한 6단계 화면을 바탕으로 기존 React/TypeScript/Vite 프론트를 구성했다.
API 현황과 다음 구현 범위는 [UI/API 기록](../docs/ui-api-plan.md), Gemini 실제 연결은 [무료 API 구동 안내](../docs/free-api-flow.md)를 참고한다.

## 실행

Node.js 20 이상.

```sh
npm ci
npm run dev
```

기본 주소는 http://localhost:5173 이다. 다른 프로세스가 포트를 사용 중이면 Vite가 출력하는 주소를 사용한다.

실제 서버를 연결하려면:

```sh
VITE_API_TARGET=http://10.1.1.27 npm run dev
```

실제 API는 VPN/서버 접근이 필요하다. 기본 프록시는 localhost:8000이다.

## 두 가지 모드

- **화면 데모** (기본): 서버 없이 홈 → 업로드 → 분석 예시 → 편집 미리보기 → 적용 상태 확인 → 공유를 경험한다. 최대 사진 4장과 본문. 예시 사진을 사용하거나 직접 업로드한다. 사진과 본문은 브라우저에 영구 저장하지 않는다.
- **실제 API**: 사진 1장+본문 또는 텍스트만 제출한다. SSE의 AWAITING_USER를 받아 리포트를 표시하고, 메모리에 유지한 최초 원본 File과 선택한 idx/action을 multipart로 transform API에 재전송한다. 서버는 최초 파일과 SHA-256 일치를 확인한다. 완료 결과를 S3에서 다운로드해 공유할 File로 준비한다.

모드 전환 및 새 작업 시작은 현재 브라우저 작업을 초기화한다. 실제 API 모드의 업로드·분석 버튼은 데이터를 서버로 전송한다.
예시 사진 버튼은 화면 데모로 전환한다. 실제 API는 무료 프로젝트 확인 후 직접 만든 합성 자료로만 검증한다.

데모의 단서 위치·위험 등급은 고정 예시다. 지우기/바꾸기는 브라우저 단색 합성, 흐리게는 Canvas 필터다. 실제 AI 분석·생성 편집·재검증이 아니며 본문도 수정하지 않는다. 심층 분석·사용자 지정 영역/자르기·자연어 수정 요청·영구 버전 관리·이전 게시물 자동 불러오기는 아직 구현하지 않았다.

## 수동 확인

1. 예시로 먼저 둘러보기 → 예시 사진과 본문 확인 → 노출 단서 찾기.
2. 단서 카드/사진 번호 선택 → 추천 보호안 보기 → 처리 방법 선택.
3. 바꾸기에서 문구 입력 → 미리보기 만들기 → 원본/결과 비교 → 적용하고 재검증.
4. 추가 보호 → 남은 단서의 그대로 두기 해제 → 새 미리보기 → 적용.
5. 잔여 위험 확인 후 계속 → 사진 다운로드 / 본문 복사 / 공유.
6. 여러 사진은 업로드 단계에서 최대 4장까지 추가하고 사진 탭과 결과 페이지의 사진 선택을 확인.
7. 실제 API 모드에서 분석 → 사용자 선택 대기 → 변환 → 결과 준비를 확인. 서버 실패/네트워크 오류는 알림으로 표시한다.

공유 버튼은 이미 다운로드된 파일과 본문을 navigator.share로 전달한다. HTTPS, 지원 브라우저, X 앱 및 실제 S3 CORS 설정을 확인해야 한다. 미지원 환경에서는 다운로드/본문 복사를 안내한다. 앱이 자동으로 X에 게시하지 않는다.

## 검사

```sh
npm test
npm run build
```

테스트는 파일 수/크기/형식, 잘못된 탐지 좌표, 여러 사진의 식별, 사진+본문 요청, AWAITING_USER SSE 종료를 확인한다. 실행 환경의 포트/Chrome 제한으로 실브라우저 시각 검증은 수행하지 못했다. 실제 서버 및 X 실기기 공유는 별도 확인이 필요하다.
