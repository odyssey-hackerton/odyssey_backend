# Odyssey React 테스트 UI

사용자가 제공한 6단계 화면을 바탕으로 기존 React/TypeScript/Vite 프론트를 구성했다.
API 현황과 다음 구현 범위는 [UI/API 기록](../docs/ui-api-plan.md), Gemini 실제 연결은 [무료 API 구동 안내](../docs/free-api-flow.md)를 참고한다.

## 실행

Node.js 20 이상.

```sh
npm ci
npm run dev
```

기본 주소는 http://localhost:5173 이다. 다른 프로세스가 포트를 사용 중이면 Vite가 출력하는 주소를 사용한다.

실제 서버를 연결하려면:

```sh
VITE_API_TARGET=http://10.1.1.27 npm run dev
```

실제 API는 VPN/서버 접근이 필요하다. 기본 프록시는 localhost:8000이다.

## 화면 흐름

| 단계 | 하는 일 |
| --- | --- |
| 01 홈 | 새 게시물 보호로 시작. 이전 게시물 점검은 준비 중 |
| 02 업로드 | 사진 최대 4장 + 함께 올릴 글 |
| 03 분석 결과 | AI ① 탐지 + ② 위험 분석 결과. **추천 보호안 보기** → 04, **심층 분석**(준비 중) → 보호 편집 없이 06 |
| 04 보호 편집 | ③이 추천한 보호를 적용한 미리보기. 영역 A, B, C …마다 가리기(흐리게/덮기)·지우기·그대로 두기. 미리보기로 결과만 보고 다시 편집 가능. **적용**하면 글에 단서가 있을 때 원래 글과 고친 글을 보여 주고 적용 여부를 고른다 |
| 05 재검증 | ③ 변환 → ② 재검증 결과. 노출 위험 전후, 처리 내역, 그대로 둔 단서·다시 찾은 단서. **추가 보호** → 04, **잔여 위험 확인 후 계속** → 06 |
| 06 공유 | 공유하기·다운로드·본문 복사 |

## 두 가지 모드

- **화면 데모** (기본): 서버 없이 전체 흐름을 확인한다. 단서 위치는 예시 카페 사진 기준의 고정 예시이고, 글은 전화번호·이메일만 찾는다. 재검증은 선택 결과를 그대로 보여 준다.
- **실제 API**: 서버는 작업 하나에 사진 1장을 받으므로 **사진마다 작업을 만들고, 글은 첫 번째 사진 작업에 함께 보낸다**(image_text). 03은 모든 작업이 `AWAITING_USER`가 될 때까지 기다린다. 04의 적용은 작업마다 원본 파일과 선택(idx/action)을 transform API로 보낸다. 글을 고치지 않기로 하면 글 단서는 `skip`으로 보낸다.
- 04 미리보기는 브라우저에서 워커와 같은 방식(덮기·지우기는 같은 단색, 흐리게는 축소 후 확대)으로 그린다. 지우기는 지금은 단색이며, 자연스러운 지우기·바꾸기·잘라내기는 준비 중이다.
- 05의 추가 보호: 완료된 작업은 다시 편집할 수 없어서, 편집된 결과 사진과 글을 새 작업으로 올려 다시 분석한 뒤 04로 간다.
- 03의 심층 분석으로 06에 가면 사진을 PNG로 다시 그려 파일 정보(EXIF)만 지운다. 찾은 단서는 그대로 남는다는 안내를 보여 준다.

사진과 글은 브라우저에 영구 저장하지 않는다. 새로고침하면 다시 선택해야 한다.

## 검사

```sh
npm test
npm run build
```

테스트는 파일 수/크기/형식, 잘못된 탐지 좌표, 사진별 작업 나누기, 리포트→단서 변환, 글 가림(워커와 같은 규칙), transform 선택, 그대로 둔 단서와 재검증 단서 짝짓기, AWAITING_USER SSE 종료를 확인한다. 실행 환경의 포트/Chrome 제한으로 실브라우저 시각 검증은 수행하지 못했다. 실제 서버 및 X 실기기 공유는 별도 확인이 필요하다.
